# 用 Grok Bot 在 2 小时内搭完一个完整 Web 应用：我的实战手记

2026 年 9 月 2 日，我想把平时收集的几个高频信息源做成一个能公开访问的聚合站。借助 Grok Bot，从构思到最终上线、接入多平台登录、部署后台并配置自动化技能，全程大约花了 **2 小时**，消耗了 **SuperGrok 额度的 30%**。

成品站点：[TopStream-AI精选资源](https://topstream-ai.vercel.app)  
代码与过程记录：[github.com/topmindspace/topstream](https://github.com/topmindspace/topstream)

这篇文章不讲空洞概念，直接把整个搭建过程拆成清晰的实操步骤，聊聊怎么让 AI 替你把脏活累活干完，而你只负责拍板关键决策。

## 成品效果

站点定位是精选目录 + 动态信息流 + 个人笔记，主要收录高价值的 AI 工具、开源项目与研究资料：

**核心功能一览：**

- **用户投稿与审核**：前台提交待审，管理后台支持一键通过或驳回。

- **对话式维护**：将“加资源”、“发笔记”打包成 Bot 自定义技能，在聊天窗口直接更新站点。

## 核心工作步骤

### 步骤 1：从真实需求出发，对话快速跑出 MVP

很多人习惯先写好 PRD 或找现成的模板，但在对话式开发中，**最好的起点是你现有的真实数据**。

- **输入原始素材**：我把工作区中已整理好的几个信息源链接和说明丢给 Bot，要求“做成一个能远程打开的分类展示站”。
- **确认核心范围**：Bot 会主动追问基础交互细节（要不要赞藏、要不要用户提交等），快速达成共识。
- **快速完成脚手架**：Bot 自主完成 Next.js 项目初始化、SQLite 数据库模型设计、响应式卡片流布局和基础后台代码编写。

这一步完全交给 Bot 自主闭环，不到半小时，一个支持分类、搜索、卡片详情的原型就在云主机上跑了起来。

---

### 步骤 2：云主机常驻 + Vercel 反代，钉死公网入口

应用跑在 Grok Bot 自带的持久 Linux 云主机上，数据库采用轻量的 SQLite。这里会遇到一个经典问题：**如何优雅、稳定地暴露公网地址？**

1. **临时隧道的局限**：使用 Cloudflare 等临时穿透隧道虽然能立刻打通外网，但域名是动态分配的，每次重启都会改变。
2. **影响关键环节**：一旦域名经常漂移，三方 OAuth 登录回调和用户书签收藏全部会失效。
3. **最终方案**：
   - 应用进程与 SQLite 数据库继续保留在常驻云主机上。
   - 前置使用 Vercel 项目反向代理（Rewrite）指向云主机的穿透端口，对外统一使用固定的 `https://topstream-ai.vercel.app`。
   - 所有外部流量、分享链接和 OAuth 回调地址全钉在 Vercel 域名上。即使底层穿透通道变更，也只需更新一次反代上游，对外完全无感。

---

### 步骤 3：接入三方 OAuth 登录，人机分工与协议避坑

登录模块支持 GitHub、Google 和 X（Twitter），这一步是典型的**人机半自动协作**：

- **人类负责的事情**：
  打开各家开发者后台创建 OAuth App，并将固定的回调地址（如 `/api/auth/callback/github`）与授权域填入，生成 Client ID 和 Secret。
- **Bot 负责的事情**：
  - 基于 Auth.js 搭建整套鉴权流程，提供本地安全配置入口（避免密钥直接打在公聊中）。
  - 处理各平台协议差异与暗坑：比如 Google 必须配置对应的 JS Origin、X 平台特殊的 Basic 认证头（`client_secret_basic`）与 token 请求头处理。
  - 配置管理员白名单机制，只有指定授权账号才允许进入审核管理后台。

这套分工非常舒适：开发者不用翻各家冗长的 OAuth 协议变更文档，只管拿密钥；底层接口调优和报错重试全部由 Bot 在命令行里实时修复。

---

### 步骤 4：把高频操作沉淀为对话「技能（Skills）」

站点上线后，如果每次新增资源或发笔记都要打开管理后台、登录账号、在表单里敲一遍，效率依然很低。

我们将日常维护工作收敛成了 Bot 的独立自动化脚本：
- **添加资源**：在对话框直接贴一条链接或推荐语，Bot 自动抓取元数据并分类写入数据库。
- **发布笔记**：直接把本地 Markdown 文件或 GitHub 仓库地址发给 Bot，管理员通道直接解析发布。

这样一来，**站点从“由 Bot 编写”转变为“由 Bot 协同运营”**，后续维护完全不需要离开对话界面。

---

### 步骤 5：UI 细节调优与长效维护

在基础功能跑通后，用 15 分钟让 Bot 进行了视觉与体验收敛：
- **克制字号与视觉层级**：去掉过于花哨的动效，保持沉稳精炼的深色卡片风格；统一导航栏字体权重，避免视觉膨胀。
- **按需加载优化**：对 Markdown 渲染器等重组件实施按需加载，提高首屏响应速度。
- **日常运维考量**：
  - **数据备份**：SQLite 数据文件在云主机持久盘上，定期自动打快照备份。
  - **进程守护**：配置进程保活机制，防止云主机环境服务意外中断。

## 总结与经验小结

回顾这 2 个小时的开发历程，总结几条最实在的心得：

1. **带环境的 AI 才是真生产力**：
   能执行命令、能常驻后台进程、能访问文件系统的 Bot，与单纯在网页文本框里吐代码的体验完全是两个维度的东西。
2. **守住人机边界**：
   - 业务逻辑、脚手架、样式调整、报错修复：放手让 AI 全自动闭环。
   - 账号密钥、三方授权、产品核心方向：牢牢掌握在自己手里。
3. **善于把一次性操作沉淀为资产**：
   做完一个功能后，顺手让 Bot 写个脚本做成技能，后续的内容运营与维护成本就会直降为零。
