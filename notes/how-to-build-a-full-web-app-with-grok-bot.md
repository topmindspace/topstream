# 如何使用Grok Bot构建一个完整功能的Web应用

2026 年 9 月 2 日，我用 Grok Bot 从一条「把几个热点信息源做成能打开的站点」的想法，做成了现在的 [TopStream-AI精选资源](https://topstream-ai.vercel.app)。大约 **2 小时**，走完产品、开发、上线、登录、域名、后台和可复用技能。这一轮大概吃掉 **SuperGrok 额度的 30%**。

这篇文章不写框架教程。重点是：在对话里，Grok Bot 怎么把「自动、半自动、引导」叠在一起，把一个能用的 Web 应用真正推到公网。

站点本身：[https://topstream-ai.vercel.app](https://topstream-ai.vercel.app)

过程笔记仓库：[https://github.com/topmindspace/topstream](https://github.com/topmindspace/topstream)

---

## 先看成品长什么样

TopStream-AI精选资源是一个精选目录 + 信息流 + 笔记站，面向「值得收藏的 AI / 效率 / 信息源」，而不是又一个万能导航。

功能（简介即可）：
- 分类目录、标签、搜索
- 资源卡片：点开、点赞、收藏、评论（未登录也能赞藏，登录后合并）
- 用户投稿：默认待审，管理员通过或拒绝（可写原因）
- 笔记：自己写 Markdown，或挂 GitHub 仓库里的 md 文件
- 侧栏「动态」：资源和最新评论混在一条流里
- GitHub / Google / X 登录；管理后台锁给 X @mspd4100 和 GitHub topmindspace
- 对话里加资源和发笔记（技能，而不是再敲一遍后台表单）

内容起点是工作区专题里的热点信息源（NewsNow、SoPilot、今日热榜、Investing、萝卜投研、REBANG），后来又收了 CyberPPT、WorkBuddy 实战蓝皮书、best-windows-apps 等。Banner 上会轮换几张推荐卡。

技术面上，应用跑在 Grok Bot 自带的那台持久 Linux 云主机上（Next.js 14、Prisma、SQLite），对外用 Vercel 反代到固定的 vercel.app 域名，OAuth 回调也钉在这个域名上。

## Grok Bot 到底在替你干什么
很多人把「AI 写代码」理解成：你复制一段，贴进编辑器。Grok Bot 更像一个能长期待在你工作流里的搭档，而且它自己有一台电脑。

这次真正用上的，大概是这几层：

1. 对话即工单。我说「做个能远程打开的资源站」，它会把范围问清楚，然后自己往下做：建项目、改 UI、修登录、写脚本。不需要我先写 PRD。
2. 自带云主机。代码、数据库、进程、浏览器登录态都留在那台机器上。下次接着改，不是每次从零 clone。隧道、Next 服务、数据库都在这里。
3. 技能可沉淀。重复动作（加一条资源、发一篇笔记）收成技能。以后在聊天里贴链接或 Markdown，它按同一套命令写入后台。
4. 需要人的地方会停下来。OAuth 密钥、控制台里点 Authorize、选域名方案，它不会假装能替我点。它把该填的 URL 列清楚，修好协议层的坑，让我只做「只有账号持有者能做」的那几下。

这和「一个聊天窗口生成代码」差很多。差在：能执行、能记住、能发布、能把过程收成下次还能用的入口。

## 三种节奏：全自动、半自动、引导式

整晚并不是一种工作模式。按「谁必须出手」切开，大致是三档。

### 全自动（我说目标，它闭环）

适合边界清楚、失败可重试、不碰我的账号密钥的事：

- 从专题笔记长出 Next 应用：类型目录、标签、搜索、卡片、后台
- 迭代 UI（导航不高亮放大、信息流留白、Banner 变矮、卡片阴影）
- 笔记模块、Markdown 渲染按需加载、待审按「资源 / 笔记」筛选
- 本地构建、重启本机服务、用 curl 探活
- 把 CyberPPT 等条目写入目录
- 写加资源、发笔记的命令行脚本，并收成技能

这类工作的体验是：我说「再收一版」，过一会儿刷新站点就能看见。中间偶尔确认一句方向，不用盯终端。

### 半自动（它搭好，我填关键一格）

OAuth 是典型。GitHub / Google / X 的 Client ID、Secret、回调 URL 只能由我在各家控制台创建。Grok Bot 做的是：

- 算出稳定回调：https://topstream-ai.vercel.app/api/auth/callback/github（以及 google、twitter）
- Google 还要加 Authorized JavaScript origin
- 在机器上接好 Auth.js，修 GitHub 的 iss、X 的 client_secret_basic 这类协议坑
- /setup 引导页帮我把密钥写进环境（它不会把密钥打到聊天里）
- 管理员名单锁到我的 X 和 GitHub 账号

我的工作量是：打开三家开发者后台，把那几个值贴进去。联调、报错、重试登录，仍然是对话里完成。

### 引导式（方案要人拍板）

域名是这一档。免费、稳定、能给 OAuth 用的主机名，选项互相打架：
- Cloudflare 临时隧道能立刻公网访问，但主机名会变，OAuth 回调会跟着炸
- is-a.dev 的 topstream 前缀当时还空着，但 DNS 在对方账户上，不能指到会变的隧道
- topstream.vercel.app 全球已占用，于是用 topstream-ai.vercel.app
- 真正稳的做法是：自己的域名 + Cloudflare 命名隧道。这要花钱、要注册，当晚没做完是对的

Grok Bot 把约束讲清楚，我不需要先成为 DNS 专家。我选「先用 Vercel 反代钉住入口」，它就去改 AUTH_URL、反代规则、OAuth 文档，而不是把临时隧道当永久地址。

一句话：能闭环的自己做；必须握着密钥的停下来等我；有长期代价的方案摊开让我选。这比「全自动幻觉」或「每一步都问我」都好用。

## 实际过程（按发生顺序）

### 1. 意图来自自己的笔记，不是空降一个 Demo

起点是 topmind 工作区里的专题：几个热点 / 财经信息源。第一句话更接近「让这些链接别人也能打开」，不是「帮我写个 Next 模板」。

后面范围是在对话里长出来的：分类、标签、搜索、赞藏评论、投稿审核、登录、笔记、动态。Grok Bot 适合这种「边做边加」。前提是你接受它先做一个能用的最小闭环，再按你的下一句往上叠。

### 2. 应用长在云主机上，而不是我的笔记本里

站点目录在云主机的工作区输出层。SQLite 也在这台机器上。所以：

- 我不需要本机装 Node 才能看效果
- 数据不会因为我关笔记本就没了（机器还在）
- 公网访问必须另开通道：先是 Cloudflare 快速隧道，再是 Vercel 反代

这也解释了后面为什么不要把带 SQLite 的整站当 Serverless 丢上 Vercel：Vercel 适合当稳定门面和 OAuth 回调域名，应用进程和数据库留在这台一直亮着的主机上更老实。

### 3. 先让世界能打开，再把地址钉死

顺序很重要：

1. 隧道起来，用临时域名验证「外网真的打得开」
2. 发现临时域名不适合做 OAuth 和分享
3. 试免费二级域名，撞上 DNS 权限和隧道变更
4. 落到 Vercel 项目反代，公开入口固定为 https://topstream-ai.vercel.app
5. 隧道 hostname 若以后变了，只改反代源，不改用户收藏的地址和 OAuth 控制台

Grok Bot 在这一步的价值不是「会配 nginx」，而是把产品约束（登录回调只能设一次）和技术约束（隧道会变）对齐，避免把试看地址写进 Google Cloud Console 然后明天全挂。

### 4. 登录：引导配置 + 它修协议

三家登录都走过。GitHub、Google 相对顺利；X 踩过 token 头和 Basic 认证的坑，修完就能进。会话默认 30 天。管理后台未登录是 403，符合预期。
半自动在这里特别明显：我不会去读 Auth.js 源码，但愿意在 /setup 里填三行。它负责「填完为什么还是失败」以及「管理员到底认哪个账号」。

### 5. 技能：把发布从后台搬回聊天

两件事被收成技能，以后不用打开 Admin：

- 加资源：聊天里丢 URL 或站点名，分类写入目录
- 发笔记：丢 Markdown，或 GitHub 上的 md 地址，默认直接发布（管理员通道）

这篇文章本身也走后一条：先落到 GitHub 仓库，再按 GitHub URL 同步进站点。技能不是装饰，是把「Grok Bot 构建站点」收成「Grok Bot 运营站点」。

UI 上刻意压了「动态 / 笔记」的字号炫耀，改成和探索、收藏一样大，选中只用颜色和边条。原因也简单：导航一旦靠放大吸引注意，整个栏会发涨。这种细活用对话改，比开一轮设计评审快。

## 额度、时间和值不值

这一轮大约 **2 小时**，从专题到可登录的公网站点，再叠笔记、技能和反代。额度上大约是 **SuperGrok 的 30%**。

贵不贵，要看对照物：
- 自己从零搭：选栈、配登录、配隧道、配三家开发者控制台、写审核后台，两小时通常还在脚手架
- 雇人做 MVP：沟通成本就超过这两个小时
- 纯聊天模型只出代码：还要我本机跑、我自己找回调填错、我自己写发布脚本

30% 换来的是可访问的产品 + 可重复的发布入口 + 一台还挂着服务的主机。对我这种「想把工作区里的东西公开出去」的用法，这个交换是划算的。它当然不是无限额度玩具，而是该用在「能变成资产」的任务上：站点、技能、工作区，而不是无尽闲聊。

## 个人体会：好用在哪，空间在哪

确实好用。不是口号。好用的点很具体：

- 我可以保持产品语言（笔记别放大字号、登录只走固定域名），不用先翻译成 issue。
- 卡住时它会改自己的实现（X 登录头、GitHub 签发字段），而不是把文档甩给我。
- 云主机让「发布」是真的发布，不是 README 里的假地址。
- 技能让第二次比第一次便宜：加资源和发笔记已经不必再讲架构。

可发挥的形式很多，值得长期用、慢慢试。不必一次做成平台。比如：
- 个人目录、读书笔记公开展示、小工具合集
- 把常用操作收成技能（记账、剪藏、发推、巡检工作区）
- 用对话做运营：改文案、改推荐位、处理待审
- 定时巡检、备份、探活（站点要长期活，这比再写功能更要紧）

云主机本身就是一个产品面。别只把它当成能跑包管理器的沙箱。它适合：

- 常驻小服务（这套导航、内部接口、定时脚本）
- 需要登录态的浏览器任务（你登一次，会话留在机器上）
- 工作区文件和数据库的落地点（和聊天记录分开，真的在磁盘上）
- 对外先隧道、再反代的实验床（验证想法，再决定买不买域名）

限制也要说清：隧道会变、数据库绑机器、登录必须人点、额度会掉。Grok Bot 把这些变成可管理的约束，而不是假装没有。

## 后续：想长期可用，还缺什么

现在的入口 https://topstream-ai.vercel.app 对分享和登录回调已经够用。要当长期产品，建议按这个顺序补：

1. 注册自己的永久域名（这是最值的一笔）。例如把 topstream 挂在你自己的域下，DNS 放在 Cloudflare。
2. 换成命名隧道，不要再用会变的临时隧道。主机名和证书固定，门面反代或直接指到隧道。
3. 三家登录控制台只保留永久域名。回调地址改一次，Google、GitHub、X 一起改，去掉临时隧道主机名。
4. 数据备份。数据库文件在云主机上，要定时拷走。机器重建不能靠「库还在聊天记录里」。
5. 探活与重启策略。进程挂了要拉起来；隧道主机名若仍可能变，反代源要能改。这可以做成对话技能或定时任务。
6. 短域名。topstream.vercel.app 已被占。自有域名之后，现在的 vercel 入口可以只当备用。
7. 不要把带本地数据库文件的应用直接部署成无状态 Serverless。继续「应用在云主机，Vercel 当门面」，或以后迁到有持久盘的小主机。
8. 内容与权限。用户投稿保持待审；对话直发只给管理员技能，避免技能变成未审核入口。

做完前三项，这个站才谈得上「收藏这个地址一年后还能打开、还能登录」。

## 若你也想用 Grok Bot 做类似的事

可以按这次验证过的顺序来：

1. 用自己已经在记的东西当种子（专题、链接、笔记），不要从空白 Demo 开始。
2. 先要一个公网能打开的最小版本，再加登录和后台。
3. 登录域名尽量一次钉死，临时隧道只用来打通。
4. 把第二次还会做的操作收成技能（加内容、发笔记、探活）。
5. 接受三种节奏：能自动的别拦，密钥自己填，有钱有约的方案自己拍。

Grok Bot 不是把程序员替换掉。它是把「想法到公网产品」之间那截最碎的活，收进持续的对话和一台还亮着的电脑。用过这一轮之后，我会继续用，也会继续试它还能托住哪些形式。目录站只是其中一种。
